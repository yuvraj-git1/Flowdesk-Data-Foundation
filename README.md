# Flowdesk Data Foundation (Project 0)

A synthetic product-led B2B SaaS data world (Jan 2023 - Dec 2025) for analyst portfolio projects:
17 analytics tables (~3.45M events, ~40K accounts, ~119K users, ~4.1K ever-paid, ~$5.9M ARR) plus a hidden `_truth` schema
with the answer key for 16 planted problems (B1-B7 billing, P1-P5 product, G1-G4 growth). Fully deterministic (seed in `config.py`), numpy/pandas only.

## Run
```
git clone https://github.com/yuvraj-git1/Flowdesk-Data-Foundation flowdesk && cd flowdesk
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python run_all.py          # ~1 min, ~400 MB disk: schema -> data/csv/*.csv -> flowdesk.duckdb + validation
```
Works from any working directory (paths are resolved relative to the scripts). Tested on Python 3.12 with numpy 2.5, pandas 3.0, duckdb 1.x; expect `ALL CHECKS PASSED`.
Quick look without building: `data/sample/*.csv` (first 1,000 rows of each public table).
Stages: `build_schema.py` (1) -> `world_a.py`/`world_b.py`/`build_world.py` (2-5, export 7) -> `load_duckdb.py` (6).
Output: `data/csv/*.csv` (and `data/*.parquet` if pyarrow exists), `flowdesk.duckdb` (`main` = public, `_truth` = hidden).

## Layout
| Path | Purpose |
|---|---|
| `config.py` | seed, pricing, targets, planted magnitudes, enums |
| `schema.py` | single source of truth for all tables/columns |
| `docs/data_dictionary.md` | public dictionary + ER diagram (spoiler-free) |
| `docs/validation_report.md` | observed metrics vs targets, key vs measured per problem |
| `data/sample/` | first 1,000 rows of each public table |

## How to use as a portfolio
Publish the `main` schema, dictionary and your analyses; keep `_truth` private until you want to grade yourself
(`_truth.answer_key` and `_truth.planted_rows` give exact affected IDs).

## Design notes and caveats
- "~4K paid" is interpreted as ever-paid; ~2.5-2.8K are active at the end. 15% sales-assisted applies to paid accounts.
- Unplanted noise (not in the key): ~35% blank industry, 2% null country, 40 internal test accounts (flowdesk.com), late-arriving events,
  2% null app_version, 0.3% void invoices, random self-reported cancel reasons, holiday/weekend seasonality.
- Experiment effects are deliberately larger than real life so they are detectable at ~3-4K users per test (true effects in `_truth.true_experiment_effect`).
- B1 affects ~313 accounts (all failed first attempts in the window); `affected_arr_usd` counts only those retries would have recovered.
- Measured G3 sales-assisted/self-serve cash LTV ratio is ~2.7x (target ~3x); tune `seat_mult` in `world_a.py` if you want 3.0.
- `load_duckdb.py` is verified end to end (all checks pass). It deletes and rebuilds `flowdesk.duckdb` on each run.
- All data is synthetic and generated by this code (no third-party data, no real people). Emails look like `user1@nan` (placeholder domain).
- Generated data (`data/csv`, `data/*.parquet`, `flowdesk.duckdb`) is git-ignored; rebuild with `run_all.py`. The answer key lives only in the `_truth` schema of the built database.
